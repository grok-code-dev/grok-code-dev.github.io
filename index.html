What the launch post actually says

The announcement is dated 25 May 2026 and is titled Introducing Grok Build. It describes a coding agent aimed at professional software engineering and complex work, running directly from the terminal, and it is explicit about who can use it: all SuperGrok and X Premium Plus subscribers, in early beta. Installation is a single line, curl -fsSL https://x.ai/cli/install.sh piped to bash, followed by signing in with the same account. The separate product page adds that the agent is now powered by Grok 4.6, described there as a new model, and repeats that access is early for those two subscription tiers. No free tier is mentioned anywhere in either page, and no per-seat figure appears either, so treat any number you read elsewhere as unverified until the pricing page confirms it.

Plan mode is the part worth caring about

For anything larger than a one-file change, the documented workflow is to start in plan mode. The agent writes a plan first, and you can approve it, comment on individual steps, or throw it out and rewrite it before a single edit lands. Once a plan is approved, every change surfaces as a clean diff rather than as silent file writes. The example in the announcement is mundane in a useful way: a request to tighten install documentation for headless mode produces a four-step plan covering the bootstrap snippet, the headless flag, a pointer to config.toml for models and API keys, and cross-links between the auth and feedback sections. That is the shape of the thing. Review first, execute second, read diffs at the end.

It reads the config you already have

One claim in the post is easy to skim past and matters a lot in practice: your AGENTS.md, plugins, hooks, skills and MCP servers work out of the box. Start the agent inside an existing repository and it picks up those conventions rather than asking you to restate them. There is also a marketplace built in, with tabs for hooks, plugins, skills and MCP servers, and the demo shows a community plugin called browser-review installed and its skills opened from inside the session. If you have already invested in that ecosystem for another agent, the migration cost here is low. If you have not, none of it is required to get started, but the ceiling is lower without it.

Parallel subagents, worktrees, and scripts

Larger tasks get delegated to specialised subagents that run at the same time, and the post says the agent supports deep worktree integrations, including launching subagents in their own worktrees. The worked example is a p99 latency regression: the work fans out into diffing recent deploys, ranking the slowest endpoints, pulling slow query plans, and checking cache hit rates, all running in parallel. Separately, a headless flag, written as -p, lets the agent run inside scripts and automations rather than in an interactive session. That combination is what makes it a build-server candidate rather than only a typing assistant, though the early beta status is a fair reason to keep it out of anything load bearing for now.

It is a separate project with separate maintainers, and nothing in the xAI announcement refers to it. Getting from search result to first session

    The published command fetches x.ai/cli/install.sh with curl and pipes it to bash. Read the script before running it if you are on a work machine, as you would with any bootstrap.

    Start the agent from inside a project that already has an AGENTS.md or MCP configuration, since picking up existing conventions is where most of the value shows up.

FAQ

Is grok code free to use?

Neither source page describes a free tier. The announcement says early beta access covers all SuperGrok and X Premium Plus subscribers, and the product page repeats that. No per-seat or per-token figure appears in either page, so check the official pricing page rather than trusting a number from a summary article.

Which model does it run on?

The product page states the agent is now powered by Grok 4.6, described there as a new model. The May announcement itself does not name a model version, which is consistent with the product page being the more recently updated of the two. If the version matters to your work, check the product page rather than the launch post.

How do I install it?

One command: curl -fsSL pointed at https://x.ai/cli/install.sh and piped into bash, then sign in with your account. That single line is what both the announcement and the product page publish, and no alternative package manager route is mentioned in either.

Can it run without a human watching?

Yes, to a point. Headless mode, written as the -p flag, is documented as a way to run the agent inside scripts and automations. Given that the whole thing is labelled early beta, running it unattended against production code is a decision to make deliberately rather than by default.
